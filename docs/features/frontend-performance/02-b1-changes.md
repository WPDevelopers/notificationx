# Phase B1: Changes and Verification

> **Status:** done in the working tree on 2026-09-22; not yet released. The `@since 3.3.2` tag on the new hook assumes the next version is 3.3.2.

B1 is the low-risk phase. It changes where code is imported from and adds one hook, without redesigning anything. Three changes are deliberate behaviour changes; everything else must render identically, and the E2E comparison shows it does.

## Changes

### B1.1 Frontend no longer imports admin modules

| File | Change |
| --- | --- |
| [nxdev/notificationx/shared/helpers.ts](../../../nxdev/notificationx/shared/helpers.ts) | **New.** Holds `getIconUrl`, `themes_has_bg` and `modalStyle`, moved verbatim. No imports at all, by rule. |
| [core/functions.ts](../../../nxdev/notificationx/core/functions.ts) | The two definitions are replaced by `export { getIconUrl, themes_has_bg } from "../shared/helpers"`. Admin imports are unchanged. |
| [core/constants.ts](../../../nxdev/notificationx/core/constants.ts) | `modalStyle` is replaced by a re-export from `../shared/helpers`. Admin imports are unchanged. |
| [frontend/core/Analytics.tsx](../../../nxdev/notificationx/frontend/core/Analytics.tsx), [Popup.tsx](../../../nxdev/notificationx/frontend/core/Popup.tsx), [Pressbar.tsx](../../../nxdev/notificationx/frontend/core/Pressbar.tsx) | Import from `../../shared/helpers`. |
| [frontend/gdpr/utils/GdprActions.jsx](../../../nxdev/notificationx/frontend/gdpr/utils/GdprActions.jsx) | `modalStyle` from shared; the cookie-deletion call uses `requestCookieDeletion()` instead of the admin `nxHelper.get()`. |
| [frontend/gdpr/utils/helper.js](../../../nxdev/notificationx/frontend/gdpr/utils/helper.js) | **New** `requestCookieDeletion()`: the same `apiFetch` request the admin helper sent (same path, `GET`, errors swallowed). |

Why it's safe:

- The moved code is byte-for-byte the same, and the admin re-exports the same objects (a unit test asserts `constants.modalStyle === shared.modalStyle`).
- The admin chain that dropped out (`core/functions.ts`, `hooks/*`, `ToasterMsg.tsx`, `@wordpress/date`, `@wordpress/deprecated`, `moment-timezone`, `sweetalert2`, `react-toastify`) has no top-level side effects the frontend relied on:
  - Importing `@wordpress/date` only registers timezone data; it doesn't change moment's global locale. The frontend's only moment call, `fromNow()` in [Theme.tsx](../../../nxdev/notificationx/frontend/themes/Theme.tsx), doesn't use timezones.
  - The frontend never calls `Swal` or toasts.
- Globals the bundle exposes (`window.sprintf`, `vsprintf`, `notificationXArr`, `notificationXClosed`) are still there. NotificationX Pro's `frontend.js` is an empty module and doesn't depend on bundled libraries.
- The moment locale chunks (`assets/public/locale/*.js`, 137 files) are unchanged.
- The admin bundle compiles; its output differs only by minifier renames. The committed `assets/admin/js/admin.js` was **not** rebuilt, because the maintainer builds admin assets. It works as is: the helpers are identical. It will be regenerated by the next `npm run build`.

### B1.2 `platform.js` only for the YouTube subscribe widget

[Analytics.tsx](../../../nxdev/notificationx/frontend/core/Analytics.tsx) computes `showYtSubscribe`, the exact condition that renders `.g-ytsubscribe`, and adds `https://apis.google.com/js/platform.js` only when it's true.

The add-on-mount and remove-on-unmount pattern is kept on purpose: re-adding the script makes Google scan the page again and render the newly mounted widget when notifications rotate. Loading it once would break the widget from the second rotation onwards.

Press bars return early and never rendered the widget, so they never needed the script.

### B1.3 GDPR "Delay Before Appearance" accepts 0

`(+config?.cookie_visibility_delay_before || 5)` became `parseDelaySeconds(config?.cookie_visibility_delay_before, 5)` ([frontend/core/functions.ts](../../../nxdev/notificationx/frontend/core/functions.ts), [useNotificationX.ts](../../../nxdev/notificationx/frontend/core/useNotificationX.ts)).

| Stored value | Before | After |
| --- | --- | --- |
| missing, `''`, non-numeric | 5 s | 5 s |
| `0` / `'0'` | **5 s** | **0 s** |
| `3`, `'2.5'` | as set | as set |
| negative | fired immediately | 0 s (same effect) |

### B1.4 New `nx_status_updated` action

[PostType::update_status()](../../../includes/Core/PostType.php) fires `do_action( 'nx_status_updated', $nx_id, $enabled, $source )` after a successful enable or disable. The list-page toggle and bulk actions go through this method and fired no hook before. Page-cache plugins need it; see [01-optimizer-compatibility.md](01-optimizer-compatibility.md). It doesn't fire when the status is unchanged or enabling is refused (`nx_can_enable`).

## Deliberate behaviour changes

1. Pages without a YouTube subscribe widget no longer load Google's `platform.js`.
2. A GDPR delay of 0 now shows the banner immediately. Sites that saved 0 used to get 5 seconds. **Put this in the changelog.**
3. The bundle no longer injects SweetAlert2's stylesheet into public pages. `sweetalert2.all.js` adds a `<style>` tag when it's imported. Nothing on the frontend used those styles.
